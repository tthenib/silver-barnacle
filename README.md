# silver-barnacle

Research and engineering for a systematic cryptocurrency trading Expert Advisor on MetaTrader 5.

**Current status: Phase 1 (research and architecture) complete. No strategy code written.**

This project optimises for robustness and honest measurement, not for backtest appearance. It
may conclude that no defensible edge exists — that is an acceptable and planned-for outcome.

## Three findings that shape everything else

**1. A 60–75% annual return requires a Sharpe ratio above 1.0 — at any leverage.**

Expected log growth is `S·σ − σ²/2`, maximised at `σ = S`. The maximum CAGR attainable at
*any* leverage is therefore `exp(S²/2) − 1`:

| True net Sharpe | Maximum possible CAGR |
|---|---|
| 0.5 | 13.3% |
| 0.7 | 27.8% |
| 1.0 | 64.9% |

A single-asset crypto trend system plausibly delivers a net Sharpe of 0.3–0.7
([RESEARCH.md](RESEARCH.md) §2.1). The target is not merely ambitious — it is arithmetically
out of reach at that Sharpe, and no amount of leverage changes that.

**2. The Sharpe we would need is inside the noise band of a routine parameter search.**

A 5-year Sharpe estimate has a standard error of ≈ 0.55. A search over 500 configurations with
**zero real edge** is expected to produce a best in-sample Sharpe of **1.37**. Any backtest
that "hits" the return target is, a priori, more likely to be selection noise than skill.

**3. Volatility targeting and the "risk 1–2% per trade" rule are incompatible at trend stop widths.**

At a 15% volatility target with a 4×ATR stop, per-trade stop risk lands at 2.8–3.6% of equity —
not a bug, but arithmetic. [RISK_MANAGEMENT.md](RISK_MANAGEMENT.md) §2 resolves this by making
volatility targeting primary and per-trade risk a capped derived quantity.

These calculations are reproducible: [`results/`](results/) is generated by
[`research/analysis/`](research/analysis/).

## Operating loop

This repository now has a small, repeatable command surface so the research charter is not just
readable, but enforceable:

```bash
make install             # install numpy/scipy for deterministic analyses
make verify              # check links; warn if result freshness cannot run locally
make verify-strict       # fail unless generated results are current
make regenerate-results  # rebuild committed analysis outputs after changing analysis code
```

If you only want the zero-dependency documentation check, run `make verify-docs`. The default
`make verify` target is developer-friendly: missing scientific dependencies are reported as a
warning, not hidden as a pass. CI uses `make verify-strict` after installing dependencies, so
generated-result drift fails before merge.

## Reproducing the analyses

```bash
pip install numpy scipy
python research/analysis/return_target_feasibility.py > results/return_target_feasibility.md
python research/analysis/lot_granularity.py          > results/lot_granularity.md
python research/analysis/research_power.py            > results/research_power.md
```

Both are seeded and deterministic. No external data.

## Standing rules

- Research is the source of truth; the EA is a port, validated by 100% signal parity.
- Signals use closed bars only, enforced structurally rather than by discipline.
- The risk engine can only reduce exposure, never increase it.
- Every trial against validation or test data is counted and carried into the Deflated Sharpe.
- The test set is opened once.
- Negative results are reported, in full, first.
- Martingale, grid, averaging down, and widening stops on losers are prohibited by design.

## What this project does not do

It does not promise profitability, optimise for a backtest, cherry-pick periods or assets,
remove losing trades, or use future information. If the evidence does not support a live
deployment, the deliverable is the evidence.
